Getting started

This guide walks a new team from a clean machine to a verified OEP install with every health check green. It is the same checklist the release build runs end to end.

What you get

  • A self-hosted PDM (oep-pdm): vault storage, revision state, roles and audit on the REST API v1.
  • A browser viewer (oep-web): item explorer, BOM tree, preview embed, and compare view, plus the PDM REST API on the same port.
  • A P2P compute dashboard (oep-opsdash): queue depth, node health, job logs, cost and energy.
  • Export/convert workers (oep-batch-convert, oep-render-worker) shipped in the same image.
  • The docs you are reading now, served by the same stack.

There is no separate database, no secret handshake, and no admin bootstrap step. Fresh state and all three services healthy is the whole install.

Prerequisites

  • Ubuntu 24.04 (aarch64 or amd64), Debian 12, or any recent VM or small server with Docker Engine 24+ running and Docker Compose v2.
  • About 5 GB free disk, curl, git.
  • For the online path: outbound internet to fetch build base images and crates. For an air-gap machine: the signed offline bundle instead (see the admin guide).

Install (one command)

Clone the repo and run the one-command install from the deploy directory:

git clone http://gitea/isolith/isolith.git isolith
cd isolith/workstreams/delivery/deploy/deploy
./install.sh

From a clean state it preflights Docker/Compose/disk, writes .env from .env.example (host binds default to 127.0.0.1), builds or loads the single stack image, starts all services, waits for every health check to go green (up to 180s), then curls each health surface and prints the operator summary. Exit code 0 means all services are healthy. 

./install.sh --down                     # stop the stack
./install.sh --offline-bundle <tarball>  # air-gap install from a signed bundle
./install.sh --no-build                  # reuse an already-built image

The eight-step checklist

Run these in order. When all eight match, the machine is a verified install.

#StepCommandExpected
1Clean statedocker ps --filter name=isolith- --format '{{.Names}}'empty (no isolith containers)
2Install./install.sh"All 3 services healthy." and exit 0
3PDM healthcurl -fsS http://127.0.0.1:8787/api/v1/health{"status":"ok","service":"oep-pdm",...}
4Viewer healthcurl -fsS -o /dev/null -w '%{http_code}' http://127.0.0.1:8790/200
5P2P healthcurl -fsS http://127.0.0.1:8080/healthz{"status":"ok"}
6Convert worker shippeddocker run --rm --entrypoint oep-batch-convert isolith/oep-stack:0.1.0 --helpusage text, exit 0
7Render worker shippeddocker run --rm --entrypoint oep-render-worker isolith/oep-stack:0.1.0 --describeJSON descriptor, exit 0
8Update checker offgrep -c 'OEP_UPDATE_CHECK=on' .env; echo $?1 (nothing found: the checker only runs when an operator points it at a source)

First actions after install

  1. Open the viewer at http://127.0.0.1:8790/ - you land on the item explorer with an empty vault catalogue.
  2. Create vault items through the REST API (POST /api/v1/items, then POST /api/v1/items/{id}/revisions) or the self-hosted client tooling. Revisions, lock/release, transitions and audit are on the PDM REST API v1.
  3. Check the P2P lane at http://127.0.0.1:8080/ - queues start empty; workers appear as nodes report in.
  4. Point the viewer at real geometry to see what the format readers can do. That is the honest format capability matrix: read it before you promise a workflow.
What this guide does not promise: it does not set up remote access (that is an admin/local-network decision), and it does not imply any file format can be read completely. The format matrix states exactly what the readers open and what fidelity they reach today.
