Release trains

Releases and changelog

Isolith runs on calendar-train versioning: the user-facing version is YYYY.N, and patches append a third segment (2027.1.1). A patch contains fixes only, never new features. The full policy is the release-train decision; this page is the plain-language index.

Where the changelog lives

The changelog is generated, never hand-written: it is built from the conventional-commit history by git-cliff and committed with each release. For 2027.1.0-rc2 it is CHANGELOG-2027.1.0-rc2.md in the repository, with its own sha256 sidecar. Release notes for installers are published as GitHub Releases, on the same page as the downloads. The repository address is the placeholder constant SITE-REPO-URL in docs-site/site.json, substituted at site generation.

Support window

Security fixes ship in a patch release of the newest published train. The immediately preceding train receives backports on a case-by-case basis, only when the fix is verified to apply. Older trains are not supported. That is the honest support surface of a single-maintainer project; the full statement is in SECURITY.md.
