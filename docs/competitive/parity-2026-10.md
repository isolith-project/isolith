## Framing

Five open or partly open CAD programs reached public attention in October 2026, four of them within four weeks, all built with heavy AI agent involvement. None is shaped like Isolith: each clones a single-user modeller's workflow (Fusion, SolidWorks, AutoCAD) and none reads CATIA formats, serves multi-user PDM, or claims an export-control posture.

Three findings change the risk picture:

1. **SolidCraft** registers a surface command set that reaches into Class-A territory, and its roadmap claims the continuity core (G0 to G3 blends, boundary, Coons and Gordon surfaces, fairing) as shipped, which weakens the premise that ICEM-class surfacing is a multi-year uncontested moat.
2. **SolidCraft's kernel migration target** (SolidCore) is an Apache-2.0, safe-Rust port of NVIDIA's SMLib with differential tests, making it a legitimate second implementation behind the `oep-geo` Evaluator seam next to the LGPL Open CASCADE binding, though its releases still run on the truck kernel today.
3. **MitCad** imports Fusion F3D/F3Z, Inventor IPT, IFC, RVT and SolidCraft's own `.solidcraft` files with feature history preserved and versions projects in git, which means editable-history import is no longer unique to Isolith.

Two of the five have more public attention than Isolith will have at launch, and neither has a product behind it that a defense supplier could buy. Attention is not capability, and the capability Isolith actually competes on is not the one the crowd is rewarding.

### SolidCraft (tangency-labs/solidcraft, `[repo]` + `[api]` + `[video]`)

- Dual MIT OR Apache-2.0, pure Rust, egui + wgpu + wasm; desktop, browser, headless CLI and an MCP server on one JSON command set `[repo]`. Created 2026-10-07; 11,262 stars, 1,421 forks, 3,822 open issues at capture; lead contributor 869 commits, then 130, 119, 107 `[api]`. v0.25.0 published 2026-10-27 `[api]`.
- Kernel: current releases run the **truck** kernel (Apache-2.0) behind its own `kernel` crate. `tangency-labs/solidcore` (Apache-2.0, created 2026-10-12, 238 stars, 179 open issues) is the **migration target**, a Rust port of NVIDIA's SMLib from NVIDIA-Omniverse/usd-brep, not in releases yet (tracking issue 4012) `[repo]`. SolidCore goals: no `unsafe`, no panics on bad input, deterministic, no global state, wasm32 target, 1e-9 relative agreement with the C++ reference with identical topology, verified unit by unit through a differential test crate; own status is honest (ports exist, coverage still partial, API 0.0.x) `[repo]`.
- Sketching: lines, rectangles, circles, arcs, polygons, slots, ellipses, fit/control splines, conics, text; construction, projection, trim, fillet and chamfer; own constraint solver (locus intersection and rigid-cluster decomposition after Owen 1991 and Fudos-Hoffmann 1997, Levenberg-Marquardt for the rest, Jacobian rank for remaining DOF); constraints include coincident, point on curve, horizontal/vertical, parallel, perpendicular, tangent, curvature (G2), equal, concentric, collinear, midpoint, symmetry, fix, plus linear/aligned/point-to-line/line-to-circle/point-to-circle/circle-to-circle/radius/diameter/angle/arc sweep/arc length/slot length dimensions driven by parameters `[repo]`.
- Features on a parametric timeline: extrude, revolve, sweep, loft, fillet/chamfer, shell, draft, holes, threads, patterns, mirror, split, combine, move; edit, suppress, rename, reorder, delete; incremental rebuild `[repo]`.
- Surfaces: the command registry lists 19 surface commands (Blend, Boundary, Extend, Extrude, Fair, Loft, Match, Offset, Patch, Reverse Normal, Revolve, Ruled, Stitch, Sweep, Thicken, Trim, Unstitch, Untrim, with `surface.fillet` the one row marked planned at issue 769) plus `inspect.continuity`, `inspect.zebra`, `inspect.curvature_map`, `inspect.curvature_comb`. Registry breadth is not shipped depth: the roadmap puts surfacing at 6 of 14 and states patch/trim/blend/match exist while the rest of the surface toolset is planned, with `surface.ruled` (762) and `surface.untrim` (761) registered but still work. The roadmap claims the continuity and blend core as shipped (G0 to G3 blends, boundary, Coons and Gordon surfaces, fairing) with a Gregory-type corner outstanding; the source tree carries class-A surface records, patch continuity, corner G2 and variable blend modules `[repo]`. Ship quality of the source-tree modules is not verified.
- Command registry breadth: 493 commands across 39 sections, of which 7 are marked planned; the project itself warns registry breadth does not establish workflow or geometric depth `[repo]`.
- Assemblies: nested components and occurrences, joints, motion studies, contact sets, interference, material-aware mass properties `[repo]`.
- Sheet metal: flanges, hems, fold/unfold/refold, material cutouts, flat patterns, bend tables, DXF outlines `[repo]`.
- Files: STEP AP242 export (body names, colours, components as assemblies, revolved faces as native analytic surfaces), STEP AP203/AP214/AP242 import, IGES 5.3, 3MF, STL, OBJ, glTF 2.0, URDF, FreeCAD FCStd and Rhino 3dm through cadmpeg, native `.sc` container `[repo]`.
- Self-assessment: "early but usable for simple parts"; `docs/oracle.md` reports 83 of 83 reference cases pass (62 analytic, 21 FreeCAD-computed), 0 known failures, while capabilities.md still carries the older 75 of 76 line; the repository states these checks do not establish geometric or workflow equivalence `[repo]` (maintainer-run, not independent).
- Not present: 2D drawings (deferred), mesh modelling, T-splines, extended surfacing beyond the set above, PCB, simulation, CAM, multi-user anything, PDM, version control, CATIA formats `[repo]`.
- LTT practitioner segment (tested at v0.16.2, an eight-day-old build at air): tabs/icons read near-identical to Fusion, single-axis snap (no simultaneous horizontal + aligned extension), sketch-solving divergence on deleting construction lines, viewport smoothness judged better than Fusion by one tester (discounted as "less feature rich"), and a fillet error dialog quoted verbatim as an honest error message. Asked "would you give up your licence": no `[video]`.

## Reconciliation with the scope register

- **Decision #19 amendment.** The register treats Class-A surfacing as a long-horizon program whose moat is the kernel and whose competition is years away. SolidCraft's surface command set and class-A source modules show a well-funded-attention competitor reaching the same door within five weeks of its first commit. The moat claim should be narrowed to sustained G2/G3 continuity across patch networks, surface quality analysis, and production-class trimming. The scope register's `class-a-surfacing` row already carries `class-4-different-foundation`; what it lacks is a defined first acceptance test: a G2 continuity result across a three-patch blend, published with residuals, as the row's `building` evidence.
- **SolidCore changes the kernel risk profile, not the kernel decision.** The OCC binding is the right 2027.1 route. The SOLIDCORE-SEAM-EVAL card landed on main on the same day (`d15e6b3`, memo `workstreams/modeler/kernel/solidcore-evaluation.md` v1.1.0 at `7dffa86`): SolidCore (Apache-2.0, pure Rust, wasm32) was evaluated against the `oep-geo` Evaluator seam, 2,551 cargo tests and the C++ differential reference passed on U1, and the verdict keeps OCC on decision #19 with three ranked options recorded for Don. The seam now has evidence a second implementation is feasible; a second implementation is the only real proof the seam is boundary-true.
- **The practitioner input contract is the cheapest acceptance test for decision #19, and its rows are now registered.** The PRACTITIONER-INPUT-CONTRACT card landed on main on the same day (`3e3d27c`): eight input-* rows (command search, right-click radial, spacebar, snap inference, escape semantics, cut-region, datum-plane legibility, tab customisation) plus undo/redo parity were added to `docs/scope-register.json` in a `practitioner_input_contract` section with the same status ceiling, two of them (`input-command-search`, `input-undo-redo-parity`) `building` with a green accepted test (`crates/oep-shell/tests/practitioner_input_contract.rs`) and the rest `planned`. The matrix's Isolith "AI agent integration" cell stays `plan`; these rows raise the editor bar, they do not claim it.
- **Interop novelty is no longer the story; interop depth is.** Isolith's answer to MitCad is not "we also import histories", it is "we read the formats nobody else reads, with published fidelity, and we can prove it on a corpus". The public narrative should name CGR, 3DXML and CATPart explicitly and point at the format matrix.
- **Positioning against price anchors.** Against Fusion at 680 USD/yr the honest pitch is ownership and air-gap, not cost. Against SOLIDWORKS plus PDM (about 5,000 to 7,000 USD per seat per year) and CATIA (7,600 to 15,700 USD), the pitch is a self-hosted stack with no per-seat fee and no foreign cloud. The clone wave has trained the market to expect free single-user CAD; Isolith should not compete there.
- **Community design should learn from the wave's failure mode, not its growth.** SolidCraft: 11,256 stars, 3,822 issues, twenty days. The board-based, card-gated, honest-claims workflow is what makes a public intake survivable, and the intake assets have now been written before the doors open (landed `dfcd233`) where SolidCraft is retrofitting after.

Where a crate exists but the capability has no green acceptance test (or no register/format-matrix row), the row says part or plan, not ship.

- The incumbent pricing figures are public list prices for single users in the USA and exclude taxes, reseller margin and multi-year discounts. CATIA figures come from the earlier Isolith research and are quote-based.
