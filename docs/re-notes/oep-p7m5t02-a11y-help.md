# OEP P7-M5-T02 theme/accessibility pass + generated help index (RE note)

Status: delivered, PR review pending
Card: P7-M5-T02 (wave-2 core, P7 modeler lane; theme/accessibility pass and
per-command docs, help index generated from command metadata)

## What this card delivers

1. Command metadata as the single source of truth for the workbench help
   surface: `crates/oep-shell/src/commands.rs` declares every command a user
   can type (load:cgr, load:3dxml, load:step, open-pdm, save-pdm, save,
   journal, help) with usage, category, one-line summary, long help, named
   arguments and examples, plus a `HELP_INDEX_VERSION`. The `help`,
   `help:NAME`, `help:--json`, `--markdown` and `--write-help-index:PATH`
   outputs are all GENERATED from this metadata; the CLI example no longer
   carries a hand-written usage block.
2. A committed per-command help index
   (`docs/re-notes/oep-workbench-help-index.md`), generated by
   `oep-workbench --write-help-index`, with a Rust drift-guard test that
   fails if the committed file and the metadata diverge. Per-command docs are
   now an artifact, not prose duplicated in two places.
3. An accessibility checklist (`workstreams/modeler/quality/accessibility-checklist.md`)
   that names a PASS/DEFERRED/N-A status for every item on BOTH surfaces the
   acceptance names: the viewer (oep-viewer) and the workbench (oep-shell).
   PASS items are asserted by automated tests on real material (the committed
   golden bracket document and the green STEP round trip); interactive-only
   items are honestly DEFERRED to the immediate-mode UI card.
4. An accessible viewer theme: `crates/oep-viewer/src/theme.rs` is the single
   source for background and part colors, the renderer consumes it, and the
   palette was brightened (value 0.9 to 1.0) because the previous default
   dropped the blue hue to about 2.9:1 against the background, below the WCAG
   1.4.11 floor. The tuned palette measures 3.4:1 worst case (blue), above
   the 3.0:1 floor with margin, asserted over the full hue sweep.

## Acceptance status (measured)

* Help index generated from command metadata: MET. The committed index is
  byte-identical to a fresh render from the metadata (drift-guard test
  crates/oep-shell/tests/help_index.rs, help_index_generated_from_metadata_is_
  committed), and the stdlib-only Python acceptance cross-checks the markdown
  sections against the source metadata so no single generator or editor can
  drift alone.
* Accessibility checklist passes on the viewer surface: MET. WCAG 1.4.11
  non-text contrast floor 3.0:1 cleared for every palette hue (worst measured
  3.4:1), render is deterministic single-frame (no auto-motion), selection
  identity is structured and not color-only, renderer uses the theme
  constants. All asserted in crates/oep-viewer/tests/accessibility_theme.rs
  on the committed golden bracket document (5 tests).
* Accessibility checklist passes on the workbench surface: MET. Registry
  covers every dispatchable command, every command is documented and
  discoverable, rendered help has no ANSI color escapes, unknown commands
  fail with an actionable error naming the token and pointing at help, and
  the JSON index covers all commands and is byte-stable. All asserted in
  crates/oep-shell/tests/help_index.rs (6 tests) and the Python acceptance.
* Exit codes measured on the rebuilt binary (P7-M5-T02 WB-A11Y-06): `help`
  exit 0; `help:load:cgr` exit 0; `help:--json` exit 0 (valid JSON, 8
  commands, version 1.0.0); `--markdown` exit 0; empty invocation exit 1;
  unknown command `bogus` exit 1 with 'failed: unknown command 'bogus': run
  'help' for the full command index'.
* No regression on the real surface: load:step of the committed
  box-reference.step still loads and journal/save-pdm/open-pdm round-trip on
  real material through the registry-driven dispatcher (exit 0).

## Honest boundaries / findings

* The interactive GUI accessibility items (focus ring, keyboard focus order,
  screen-reader integration, GUI zoom and click-target sizes) cannot pass on
  a headless surface and are DEFERRED with their gate to the P7-M5
  immediate-mode UI card (VW-A11Y-07, WB-A11Y-08). They are not claimed.
* The viewer was merged onto this branch so the "viewer surface" named by the
  acceptance exists and is tested here; oep-viewer (P6-M5-T02) is its own
  PR and this card carries the merged surface.
* The default part palette changed (brighter). No committed golden image is
  byte-locked, so existing render tests stay green; the change is the
  accessibility fix itself.
* Example exit-code checks are not run inside `cargo test` (CARGO_BIN_EXE_ is
  not set for example targets on this toolchain), so they are measured in
  this note on the rebuilt binary instead of asserted in a unit test. The
  help/error LOGIC is unit-tested (validate_token, render_*), which is the
  part that can regress silently.
* Serde is not introduced: the JSON index is hand-rendered (std-only),
  matching the crate's dependency-free posture.
