# P4-M1-T03: STEP Accuracy Harness (Hausdorff / Volume Geometry Diff)

## What this is

The geometry-fidelity harness for the P4 STEP lane: it diffs STEP geometry
against the native source sample of the same part **when both are present in
the corpus**, and emits a fidelity report. Deliberately honest-by-construction:

- a pair is **measured** only when real, readable geometry was imported on BOTH
  sides and the metrics were computed (symmetric vertex-sampled Hausdorff +
  signed divergence volume compare);
- anything that can't be read is a **classified skip** from a closed taxonomy
  with a machine reason — the harness NEVER invents a fidelity number.

## Pair list and outputs

- Pair list: `corpus/accuracy-pairs.json` (schema v1). Today it carries the
  committed real-material pair **keelworks-box**: native
  `corpus/data/box.stl` (CC0 unit box, 8 verts / 12 tris) and STEP
  `crates/oep-geo/tests/golden/box-reference.step` (facetted AP214 passthrough
  from the SAME reference tessellation, P6-M4-T01).
- Report: `corpus/accuracy-report.json` + `corpus/accuracy-report.md`
  (generated by the harness, committed).
- CLI: `PYTHONPATH=python python3 -m oep_tooling.step_fidelity --pairs
  corpus/accuracy-pairs.json --corpus corpus --out corpus`.

## Metrics (honest method disclosure)

- `symmetric_hausdorff`: two-sided vertex-sampled Hausdorff. For every vertex
  of mesh A the exact minimum distance to the triangle mesh B is computed, and
  vice versa; the report states `method: "vertex"` and the na/nb counts. This
  is a lower bound on the true surface Hausdorff — never claimed as exact.
- `volume`: signed divergence-theorem volume (exact for closed, consistently
  wound shells). The report exposes BOTH sides' signed volumes plus
  `volume_delta` and `volume_rel_error`, so a mixed-winding fixture is visible
  as an honest observation (e.g. the box fixture itself has mixed winding →
  signed vol -1/3 on BOTH sides, delta 0.0) rather than hidden.
- Also reported: vertex/triangle counts per side (tessellation density).

## Clean-room / scope boundary

- The STEP reader (`step_fidelity.read_faceted_step`) understands ONLY the
  facetted/tessellated subset our own P6-M4-T01 and P2-M5-T02 exporters emit:
  CARTESIAN_POINT, POLY_LOOP, FACE_OUTER_BOUND, FACE_SURFACE(PLANE),
  CLOSED_SHELL, plus the AP214/203 header/preamble plumbing. Analytic B-Rep
  STEP (ADVANCED_FACE, B_SPLINE_*, MANIFOLD_SOLID_BREP, ...) raises
  `NotFaceted` → classified `not-faceted` skip, never a number.
- When P4-M1-T01's full `oep-step` reader lands, it can be swapped into the
  same `read_faceted_step` seam (library call or external CLI) without changing
  the runner/report surface.
- Native readers in this card: STL (ASCII + binary), stdlib-only. CGR/3DXML
  native geometry is out of this card's scope (P2/P3 readers are Rust crates);
  a CGR/3DXML native pair would classify `native-unreadable` honestly rather
  than fabricate, until a native-reader hook is added (mirrors regression.py's
  OEP_CGR_READER pattern — planned via CLI `--` extra pairs / env hook).

## Skip taxonomy (closed set)

pair-missing-on-disk | native-unreadable | step-unreadable | not-faceted |
no-native-geometry | no-step-geometry | io-error

There is NO `fail` bucket: an introspection error becomes a classified row;
a crash in one pair never aborts the sweep (per-pair try/except).
