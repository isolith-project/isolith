# STL export for the internal tessellation mesh (P2-M2-T02)

Status: delivered 2026-10-15 on branch `task/stl-export-1015a` (PR #38).
Scope: binary + ASCII STL writer over the vertices/indices/triangles
representation shared with P2-M2-T01. No panics, typed errors, byte-for-byte
golden-file lock.

## What the writer does

`oep_cgr::stl` exposes two pure functions over plain slices so it is
independent of the (sibling, unmerged) `mesh::Mesh` type yet trivially
callable from it:

- `write_binary_stl(positions: &[[f32;3]], triangles: &[[u32;3]], out)`:
  80-byte zero header, `u32` LE triangle count, then 50 bytes per triangle
  (facet normal 3xf32 + 3 vertices 9xf32 + u16 attribute byte count = 0).
  Byte-stable for a given mesh (little-endian, exact f32).
- `write_ascii_stl(...)`: legacy `solid` syntax, shortest round-trip float
  formatting, byte-stable.
- `StlError::{IndexOutOfRange, DegenerateTriangle, Io}`; triangle indices are
  bounds-checked before any write; zero-area facets are rejected.

Facet normals are the right-hand-rule unit normal of each triangle
(pure interchange hygiene — the STL spec does not require readers to trust
them, and most recompute).

## Golden-file test against a reference tessellation

Reference tessellation: `corpus/data/box.stl` — the keelworks-authored
CC0-1.0 unit-box fixture (P0-M4-T02), 8 vertices / 12 triangles.

The committed golden `crates/oep-cgr/tests/golden/box-reference.bin.stl`
(684 bytes = 84 + 12*50) is generated by
`crates/oep-cgr/tools/gen_golden_box.py`, an INDEPENDENT spec encoder —
NOT by the Rust writer. `tests/golden_stl.rs` then asserts the writer's
output equals that golden byte-for-byte, proving spec conformance rather
than self-consistency.

Real-material leg: when `OEP_CORPUS=<corpus/data dir>` is set (or a
`box.stl` is found under `samples/`, `../samples/`, `../corpus/data/`), the
corpus `box.stl` is read and its 12 facets / 36 vertex coordinates are
required to be preserved exactly through the reference mesh. Tolerant SKIP
in CI until corpus PRs (#30/#33) merge — same pattern as the sibling
`OEP_CGR_SAMPLES` leg.

## Notes / Fidelity budget (feeds P2-M2-T04)

- Coordinates are stored and written as `f32` (matching CGR and STL). For
  the unit box the 0/1 corners are exact, so the golden is byte-exact.
  Nominal reference-point drift budget: STL f32 ~7 significant digits.
- ASCII STL output is ~3.2x binary size for this mesh (2196 vs 684 bytes)
  — binary is the recommended interchange default.
- No dedup/quantization: mesh passes through as extracted (P2-M2-T04
  compares vertex counts vs native).
