# P4-M2-T02: PMI re-export to AP242 — correctness tests (over and back)

Version 1.0, 2026-10-16. Milestone: P4-M2-T02 (PMI re-export to AP242 with
correctness tests). Program: Keelworks / Open Engineering Platform (OEP),
P4 STEP AP242 PMI lane. Clean-room: the entity emission follows the *public*
ISO 10303-242 MIM structure and mirrors how the NIST MBE PMI test models
(`nist_*_ap242-*.stp`, public-domain NIST data) represent semantic PMI; no
vendor schema or code is embedded.

## What the card delivers

- `crates/oep-step` gets an **AP242 semantic-PMI writer**
  (`oep_step::pmi::writer`) that maps an internal `oep_pmi::PmiDocument`
  (the oep-pmi GD&T / datum / note model, P6-M1-T02) onto an AP242
  ISO 10303-21 file, and a **round-trip reader** (`oep_step::pmi::reader`)
  that re-imports the emitted subset back into a `PmiDocument`.
- **Correctness tests** on real material, three independent gates:
  1. Round-trip: build the canonical bracket PMI doc -> export to AP242 ->
     re-import -> every datum / frame / tolerance / note field matches
     **within tolerance** (`crates/oep-step/tests/pmi_ap242_roundtrip.rs`).
  2. **Independent reader**: the committed golden export is re-parsed with
     `steputils` (independent OSS PART 21 reader, MIT, unrelated codebase)
     and the semantic PMI is re-asserted structurally
     (`tests/test_oep_step_ap242_acceptance.py` — also has a stdlib-only
     fallback so it runs on a bare CI box).
  3. Golden byte-lock: the writer is deterministic and the committed golden
     is locked by a Rust test and regenerated by
     `crates/oep-step/examples/gen_golden_ap242.rs` (`OEP_STEP_REGEN=1`).
- This file is the honest PASS/FAIL matrix for what the re-export covers.

## Entity mapping (internal model -> AP242 MIM)

| oep-pmi class                          | AP242 emission |
|----------------------------------------|----------------|
| `Datum` (label, feature ids)           | `DATUM(id|feature, $, #pds, .F., 'label')` |
| `DatumFrame` -> refs by precedence     | `DATUM_SYSTEM` + one `DATUM_REFERENCE_COMPARTMENT` per ref (1=primary first), optional `SIMPLE_DATUM_REFERENCE_MODIFIER` for MMC/LMC/RFS |
| `GeometricTolerance.characteristic`    | concrete AP242 subtype leaf: `POSITION_TOLERANCE`, `FLATNESS_TOLERANCE`, `PERPENDICULARITY_TOLERANCE`, `ANGULARITY_TOLERANCE`, `PARALLELISM_TOLERANCE`, `STRAIGHTNESS_TOLERANCE`, `ROUNDNESS_TOLERANCE`, `CYLINDRICITY_TOLERANCE`, `LINE_PROFILE_TOLERANCE`, `SURFACE_PROFILE_TOLERANCE`, `CONCENTRICITY_TOLERANCE`, `SYMMETRY_TOLERANCE`, `CIRCULAR_RUNOUT_TOLERANCE`, `TOTAL_RUNOUT_TOLERANCE` |
| `GeometricTolerance.value`             | qualified `LENGTH_MEASURE_WITH_UNIT(LENGTH_MEASURE(v), <length unit>)` in document units |
| `GeometricTolerance.frame_id`          | `GEOMETRIC_TOLERANCE_WITH_DATUM_REFERENCE((#datum_system))` complex member |
| `GeometricTolerance.material_condition`| `GEOMETRIC_TOLERANCE_WITH_MODIFIERS((.MAXIMUM_MATERIAL_REQUIREMENT. / .LEAST_... / .REGARDLESS_OF_FEATURE_SIZE.))` |
| `GeometricTolerance.diameter_zone`     | `TOLERANCE_ZONE` + `TOLERANCE_ZONE_FORM('cylindrical or circular')` whose target is the tolerance |
| `GeometricTolerance.second_value`      | second tolerance + `GEOMETRIC_TOLERANCE_RELATIONSHIP('composite', ...)` |
| `GeometricTolerance.feature_ids`       | carried in the toleranced `SHAPE_ASPECT` name (round-trip restore) |
| `Note` (id, text, feature ids)         | `DESCRIPTIVE_REPRESENTATION_ITEM(id|feature, text)` in a notes `REPRESENTATION` | 
| document units `mm`/`in`/`m`           | `GLOBAL_UNIT_ASSIGNED_CONTEXT` with the mapping length unit |

Non-ASCII note text (e.g. `Ø`) is emitted as the ISO 10303-21 `\X2\<hex4>\X0\`
escape and both the Rust reader and the acceptance test decode it.

## How to regenerate the golden

```
cd <worktree>
OEP_STEP_REGEN=1 cargo run -p oep-step --example gen_golden_ap242
```

The golden path is `crates/oep-step/tests/golden/example-bracket-ap242.stp`;
a drift in the writer or the golden is caught on either side (Rust byte-lock
or Python independent re-parse).
